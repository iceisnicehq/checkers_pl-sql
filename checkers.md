## ♟️ Только Oracle: «Шашки»
### 1) Цель
Обеспечить серверную реализацию классических шашек с ведением партий, историей и рейтингами. Взаимодействие происходит через SQL-клиенты: чтение/запись строк, чтение представлений/отчётов и получение текстовых сообщений. GUI отсутствует.

---

### 2) Ограничения интерфейса
* Логика игры выполняется **только** на сервере Oracle.
* Пользовательские действия: создать партию, делать ходы, получать статус, просматривать протокол/историю/рейтинги.
* Вывод — текстовые сообщения и табличные представления. Форматы и схемы — на усмотрение исполнителя, но должны быть стабильны и документированы.

---

### 3) Термины и правила
* Базовый режим — **русские шашки 8×8** (тёмные клетки, белые начинают).
* **Простые**: ходят по диагонали **вперёд** на 1 клетку; **бьют** вперёд и назад.
* **Дамка**: ходит по диагоналям на **любое число** клеток; при взятии может приземляться на **любой свободной** клетке за бьющей.
* **Взятие обязательно**. При наличии нескольких вариантов взятия игрок обязан выбирать **маршрут с максимальным числом взятий** (при равенстве — любой из максимальных).
* **Многошаговое взятие**: после каждого взятия шашка/дамка обязана продолжать, если возможно. Снятие побитых — по завершении маршрута (или по зафиксированным правилам, но результат идентичен).
* **Превращение**: простая, достигшая последней горизонтали, немедленно становится дамкой и (если возможно) продолжает взятие уже дамкой.
* **Пат**: отсутствие хода — поражение стороны, которой ходить.
* **Ничья**: по соглашению; по истечению лимита без взятий; по повтору позиции.
* Возможность запуска одновременно нескольких игровых сессий, в том числе с разных терминалов.
* Под одним пользователем одновременно может быть запущена только одна игровая сессия. При попытке запустить вторую должно быть корректное предупреждающее сообщение.
* При длительном простое игровая сессия должна автоматически корректно завершаться.

*Примечание: расширенные варианты (международные 10×10, «английские» и др.) — см. уровни требований.*

---

### 4) Уровни требований
#### 4.1 На удовлетворительно
1.  Создание партии в базовом режиме (русские 8×8), **2 игрока PvP**.
2.  Выполнение **валидных ходов** с проверкой правил: обязательное взятие, максимальный маршрут, превращение, многократные взятия, пат/матч-финиши.
3.  **Протокол партии** (хронологический список ходов и событий).
4.  **История** партий и **топ** игроков по метрике «успех = победы / поражения» (поведение при 0 в знаменателе описано в отчёте).

---

#### 4.2 На хорошую оценку
**Дополнительно**
1.  **Параметры партии** при создании:
    * вариант правил: русские 8×8 / международные 10×10;
    * **лимит на ход** (например, 60 с) и/или **лимит на партию**;
    * порог ничьей **N полуходов без взятий** (значение по умолчанию), включение/выключение **повтора позиции** как основания ничьей.
2.  **Представления состояния**: компактная текстовая запись позиции и очереди хода (например, единая строка), читаемый сводный статус.
3.  **Режим задач/задачника**: старт из произвольной позиции (валидатор валидности позиции), учёт решения (время/число ходов).
4.  **Отчёты**: история игрока за период, свод побед/поражений/ничьих, средняя длина партии, завершения по времени.
5.  **Доступ «наблюдателя»** (только чтение статуса/протокола по активным партиям).

---

#### 4.3 На отлично
**Дополнительно**
1.  **Ежедневная позиция** (Daily) с общим идентификатором дня и таблицей результатов.
2.  **Серии/матчи**: best-of-N с чередованием цвета, суммарный результат.
3.  **Рейтинги** (локальные) по итогам матчей/серий, сезонные таблицы.
4.  *Выбор игры* **PvE**: игра против сервера с уровнями сложности; требование — ход сервера в пределах SLA, валидность ходов по тем же правилам.

---

### 5) Бизнес-правила и валидации
* **Обязательное взятие и максимум**: если взятие есть, ход без взятия запрещён; из всех цепочек взятия выбирается цепочка с максимальным числом снятых фигур.
* **Траектории**:
    * простая ходит на 1 клетку вперёд; бьёт по диагонали на 2 клетки (или цепочкой), вперёд/назад;
    * дамка ходит на любое число клеток, бьёт с «пролётом» и произвольным приземлением за бьющей.
* **Многократное взятие**: повторный заход на одну и ту же клетку допускается только если это не приводит к «повторному снятию» уже снятой фигуры; повторное взятие одной и той же фигуры невозможно.
* **Превращение**: немедленно в момент достижения последней горизонтали; при возможности взятия — продолжение уже в статусе дамки.
* **Ничьи**:
    * по **N полуходов без взятий** (значение по умолчанию фиксируется в требованиях к отчёту/параметрам партии);
    * по **повтору позиции** заданное число раз (например, трёхкратный повтор), если опция включена;
    * по соглашению сторон (явное завершение).
* **Ходы «не своей очереди»**, изменения уже завершённой партии, ходы, нарушающие формат нотации — отклоняются.
* **Конкурентность**: одновременные попытки сделать ход в одной партии не приводят к «двойному ходу»; принимается ровно один валидный ход в корректной очереди.

---

### 6) Нефункциональные требования
* **Производительность**: при обычной нагрузке отклик на ход — интерактивный (целевой SLA, например, ≤ 300 мс); проверки ничьих/повторов не блокируют ввод.
* **Масштаб**: хранение ≥ 1 млн ходов и ≥ 100 тыс. партий без деградации ключевых запросов (при корректной индексации — зона ответственности исполнителя).
* **Надёжность**: консистентность статусов партии при параллельных запросах; отсутствие «потерянных» или дублированных ходов.
* **Аудит**: фиксируются значимые события (создание/завершение партии, ходы, отклонённые попытки, финиши по времени).
* **Обслуживание**: предусмотрены механизмы завершения «подвисших» партий по тайм-ауту параметров.

---

### 8) Отчёты/представления, доступные пользователю
* **Статус партии**: идентификаторы участников, вариант правил, очередь, таймеры, текст позиции, последний результат валидации.
* **Протокол партии**: нумерованные ходы, отметки взятий/превращений/окончаний.
* **История игрока**: список партий с результатом/временем/длиной, фильтры по периоду и варианту правил.
* **Рейтинги/топ**: по «успеху», по количеству побед/ничьих/поражений, по среднему числу ходов.
* **Daily/задачник** (если включены): условия дня/задачи и результаты.
