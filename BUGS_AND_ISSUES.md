# 🔍 Анализ багов и недочетов в game_logic.pkb

## ❌ КРИТИЧЕСКИЕ БАГИ

### 1. **Лимит времени на партию (`p_time_limit_game_sec`) НЕ РЕАЛИЗОВАН**
**Местоположение**: `create_game`, `p_process_move`
**Проблема**: Параметр `p_time_limit_game_sec` принимается при создании игры, но нигде не проверяется и не используется. Лимит времени на всю партию не работает.
**Требование**: README.MD пункт 4.2: "лимит на партию"
**Решение**: Добавить проверку в `p_process_move` или создать отдельный scheduler job для проверки общего времени партии.

### 2. **Проверка повторения позиции не учитывает очередь хода**
**Местоположение**: `p_process_move`, строка 1698
**Проблема**: Проверка `SELECT COUNT(*) FROM game_moves WHERE game_id = p_game_id AND board_position = v_new_board_encoded` не учитывает `current_turn`. Одна и та же позиция с разной очередью хода - это разные позиции.
**Пример**: Позиция "abc123" при ходе белых и та же позиция "abc123" при ходе черных - это разные позиции.
**Решение**: Добавить проверку `current_turn` в условие или хранить позицию вместе с очередью.

### 3. **Правила взятий для русских шашек не соответствуют README.MD**
**Местоположение**: `find_all_player_moves`, строки 613-615
**Проблема**: В README.MD сказано: "**Взятие обязательно**. При наличии нескольких вариантов взятия игрок обязан выбирать **маршрут с максимальным числом взятий**". Но в коде для `rule_id=1` (русские) разрешено выбирать ЛЮБОЕ взятие.
**Текущий код**:
```sql
IF p_rule_id = 1 THEN 
    RETURN v_capture_moves; -- Разрешено ЛЮБОЕ взятие
```
**Ожидаемое поведение**: Для русских шашек тоже нужно выбирать максимальное взятие (как для международных).
**Решение**: Убрать исключение для `rule_id=1` и применять правило максимального взятия для всех правил.

## ⚠️ СРЕДНИЕ ПРОБЛЕМЫ

### 4. **Матчи: отсутствует логика создания следующих игр**
**Местоположение**: `create_match`, `p_process_move`
**Проблема**: После завершения игры в матче (статус 'V', 'D', 'T', 'R') не создается следующая игра матча. Матч создает только первую игру, но не продолжается автоматически.
**Требование**: README.MD пункт 4.3: "Серии/матчи: best-of-N с чередованием цвета"
**Решение**: Добавить триггер или логику в `p_update_ratings`/`p_process_move`, которая:
   - Проверяет, является ли игра частью матча
   - Подсчитывает победы каждого игрока
   - Если никто не достиг `games_to_win`, создает следующую игру с чередованием цвета
   - Если кто-то достиг `games_to_win`, завершает матч

### 5. **Превращение в дамку при взятии: только для русских шашек**
**Местоположение**: `find_capture_paths`, строка 405
**Проблема**: Превращение в дамку при взятии реализовано только для `rule_id=1` (русские). Для международных шашек (`rule_id=2`) превращение происходит только в конце хода, но не во время взятия.
**Вопрос**: Это может быть правильным поведением для международных шашек, но стоит проверить правила.

### 6. **Отсутствует проверка на "повторное взятие одной и той же фигуры"**
**Местоположение**: `find_capture_paths`
**Проблема**: В README.MD сказано: "повторное взятие одной и той же фигуры невозможно". В коде есть проверка `v_is_visited`, но она проверяет только `captured_idx`. Если фигура переместилась, это может не сработать.
**Текущая проверка**: Строка 380-385 проверяет `p_visited_path(k).captured_idx = v_capture_idx`
**Решение**: Проверка выглядит корректной, но стоит добавить комментарий для ясности.

## 📝 НЕДОЧЕТЫ И УЛУЧШЕНИЯ

### 7. **Отсутствует валидация начальной позиции в `create_puzzle`**
**Местоположение**: `create_puzzle`
**Проблема**: Проверяется только размер доски и наличие фигур, но не проверяется валидность позиции (например, фигуры на светлых клетках, невозможные позиции).
**Решение**: Добавить более строгую валидацию позиции.

### 8. **Нет проверки на "подвисшие" игры при старте системы**
**Местоположение**: Отсутствует
**Проблема**: Если система перезапускается, scheduler jobs для таймаутов могут быть потеряны. Нет механизма восстановления.
**Решение**: Добавить процедуру инициализации, которая проверяет активные игры и воссоздает необходимые jobs.

### 9. **Информация о матчах в `info` неполная**
**Местоположение**: `info`, секция 6
**Проблема**: В справке не описано, как работает автоматическое создание следующих игр в матче (потому что это не реализовано).
**Решение**: После реализации пункта 4, обновить документацию.

### 10. **Потенциальная проблема с конкурентностью в `make_move`**
**Местоположение**: `make_move`, строка 2793
**Проблема**: В `make_move` выполняется `SELECT * INTO v_game FROM games WHERE game_id = v_game_id` БЕЗ `FOR UPDATE`, затем вызывается `p_process_move`, который делает `FOR UPDATE`. Между этими операциями состояние игры может измениться.
**Текущее поведение**: Не критично, так как `p_process_move` все равно блокирует строку, но может привести к лишним проверкам.
**Решение**: Добавить `FOR UPDATE` в `make_move` или убрать проверку статуса перед вызовом `p_process_move` (так как `p_process_move` сам проверит статус).

### 11. **Логика подсчета ходов без взятий может быть неточной**
**Местоположение**: `p_process_move`, строки 1654-1694
**Проблема**: Подсчет `v_moves_without_capture` включает текущий ход, но текущий ход еще не записан в `game_moves`. Это может привести к неточностям.
**Решение**: Проверить логику подсчета - возможно, нужно считать по-другому.

### 12. **Отсутствует валидация параметров при создании игры**
**Местоположение**: `create_game`
**Проблема**: Не проверяется, что `p_time_limit_move_sec > 0`, `p_time_limit_game_sec > 0`, `p_draw_moves_limit > 0` и т.д.
**Решение**: Добавить валидацию параметров.

IF v_capture_moves.COUNT > 0 THEN

### Исправление #2: Лимит времени на партию
**Файл**: `testdir/game_logic.pkb`, процедура `p_process_move`
**Решение**: Добавить проверку в начале `p_process_move`:
```sql
-- Проверка лимита времени на партию
IF v_game.time_limit_game_sec IS NOT NULL THEN
    DECLARE
        v_elapsed_sec NUMBER := (SYSDATE - v_game.start_time) * 86400;
    BEGIN
        IF v_elapsed_sec >= v_game.time_limit_game_sec THEN
            p_drop_move_timeout_job(p_game_id);
            UPDATE games 
            SET status = 'T', 
                end_time = SYSDATE,
                winner_player_color = CASE v_player_color WHEN 'W' THEN 'B' ELSE 'W' END
            WHERE game_id = p_game_id;
            p_status_message := 'Игра завершена по таймауту (превышен лимит времени на партию).';
            p_update_ratings(p_game_id);
            COMMIT;
            RETURN;
        END IF;
    END;
END IF;
```
